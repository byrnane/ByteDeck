# Руководство По Темам ByteDeck

Эта документация объясняет темы ByteDeck нормальным человеческим языком.

Если ты открываешь `config/themes/default/theme.json` и видишь там "кучу магических цифр", то смысл файла именно в этом документе.

## Общая Модель

UI в ByteDeck разделён на две части:

- `config/ui/screens/*.json` описывает **что находится на экране**
- `config/themes/<theme-id>/theme.json` описывает **как это должно выглядеть**

То есть:

- layout-файлы отвечают за структуру
- theme-файлы отвечают за внешний вид

Темы **не** содержат:

- игровую логику
- навигационную логику
- запуск эмуляторов

## Что Тема Может Менять

Сейчас тема может менять:

- цвета
- отступы
- масштаб текста
- заливки и рамки панелей
- style presets, которые навешиваются через classes
- выбор variant для конкретного экрана

Сейчас тема не может:

- придумывать новое поведение экранов
- подменять логику приложения
- выполнять код или выражения

## Структура Theme-файла

Каждая тема лежит здесь:

```text
config/themes/<theme-id>/theme.json
```

Текущая встроенная тема:

```text
config/themes/default/theme.json
```

Верхний уровень такой:

```json
{
  "tokens": {},
  "styles": {
    "types": {},
    "classes": {},
    "ids": {}
  },
  "screen_variants": {}
}
```

## 1. Tokens

`tokens` это переиспользуемые именованные значения.

По сути это переменные.

Пример:

```json
"spacing": {
  "xs": 4,
  "sm": 8,
  "md": 16,
  "lg": 24
}
```

Это значит:

- `4`, `8`, `16`, `24` не случайные числа
- это стандартные шаги отступов для темы

Ещё пример:

```json
"text": {
  "primary": [245, 241, 230, 255],
  "muted": [147, 157, 176, 255]
}
```

Это цвета в формате:

```text
[R, G, B, A]
```

Где:

- `R` = red
- `G` = green
- `B` = blue
- `A` = alpha / прозрачность

То есть:

```json
[245, 241, 230, 255]
```

означает:

- очень светлый тёплый текст
- полностью непрозрачный, потому что alpha = `255`

## 2. Styles

`styles` это переиспользуемые правила оформления.

Они разбиты на три группы:

- `types`: стиль по умолчанию для типа узла, например `screen`, `text`, `panel`
- `classes`: именованные style presets
- `ids`: точечные overrides для конкретного layout node

Приоритет такой:

1. runtime defaults
2. стиль по типу узла
3. стили по class
4. стиль по id
5. inline-значения в layout JSON

Если что-то выглядит "не так", проверять надо именно в таком порядке.

## 3. Screen Variants

`screen_variants` говорит renderer'у, какой layout-variant брать для конкретного экрана.

Пример:

```json
"screen_variants": {
  "main_menu": "hero"
}
```

Это значит:

- экран `main_menu` описан в `config/ui/screens/main_menu.json`
- в этом файле есть несколько variant'ов
- активная тема выбирает variant `hero`

Если variant не указан, ByteDeck откатывается к `default`.

## Ссылки На Tokens

Внутри `styles` можно ссылаться на tokens через `$`.

Пример:

```json
"fill_color": "$colors.background.panel_primary"
```

Это значит:

- пойти в `tokens.colors.background.panel_primary`
- взять это значение сюда

Это похоже на CSS variables, только сильно проще.

## Основные Типы Значений

### Цвета

Обычно пишутся так:

```json
[r, g, b, a]
```

Пример:

```json
[26, 31, 42, 255]
```

### Числа

Используются для:

- отступов
- padding
- ширины рамки
- ширины и высоты

Пример:

```json
"padding": 24
```

### Проценты

Некоторые размеры можно задавать строкой:

```json
"width": "50%"
```

Это значит 50% от родительской области.

### Fill

Некоторые размеры можно задавать так:

```json
"height": "fill"
```

Это значит "занять всё оставшееся доступное пространство".

## Самые Важные Classes В Текущей Теме

Вот основные строительные блоки:

- `screen-brand`: большой верхний логотип
- `screen-title`: основной заголовок экрана
- `screen-subtitle`: вторичный подзаголовок
- `panel-primary`: фон основной панели
- `panel-secondary`: фон правой/детальной панели
- `menu-card-*`: карточки главного меню
- `system-tile-*`: плитки систем
- `browser-list-item-*`: строки списков игр и приложений
- `preview-frame`: контейнер превью-картинки
- `status-success`: успешный статус запуска
- `status-error`: статус ошибки

## Почему Здесь Так Много Похожих Цветов

Это сделано специально. Тема отдельно хранит:

- цвет внешней рамки
- цвет внутренней заливки
- цвет выбранной рамки
- цвет выбранной внутренней заливки
- цвет приглушённого текста
- цвет выделенного текста

Без этого UI быстро становится плоским и плохо настраиваемым.

## Быстрый Старт: Что Менять Безопаснее Всего

Если хочешь быстро поменять внешний вид без риска всё сломать, начинай с этого:

1. меняй `tokens.colors.background`
2. меняй `tokens.colors.text`
3. меняй `tokens.spacing`
4. меняй `tokens.typography`

Эти изменения дают заметный результат и почти не ломают layout.

## Пример: Сделать Тему Контрастнее

```json
"text": {
  "primary": [255, 255, 255, 255],
  "muted": [180, 190, 205, 255],
  "highlight": [255, 196, 92, 255],
  "error": [235, 120, 120, 255]
}
```

## Пример: Сделать Интерфейс Плотнее

```json
"spacing": {
  "xs": 2,
  "sm": 6,
  "md": 12,
  "lg": 18,
  "xl": 28,
  "xxl": 40
}
```

## Пример: Переключить Variant Главного Меню

```json
"screen_variants": {
  "main_menu": "default"
}
```

Это меняет только layout-variant, который использует тема.

Навигационную логику это не меняет.

## Как Связаны Layout И Theme

Layout-файл говорит что-то вроде:

- здесь есть `panel`
- внутри него есть `list`
- у каждого item есть текст и рамка

Theme-файл говорит что-то вроде:

- у panel такой цвет заливки
- у выбранного item такой цвет выделения
- у заголовка такой масштаб текста

То есть:

- layout = структура
- theme = внешний вид

## Частые Проблемы

### "Я поменял token, но ничего не изменилось"

Возможные причины:

- этот token вообще нигде не используется
- его перекрывает class
- его перекрывает inline-значение в layout

### "Я поменял class, но изменился только один виджет"

Обычно это значит:

- этот class используется только в одном месте
- или его перебивает более специфичный `id` / inline override

### "Экран стал выглядеть сломанным"

Чаще всего причина в одном из этого:

- слишком маленькие отступы
- неудачное сочетание width/height
- alpha случайно поставили в `0`
- ошибка в JSON

Если layout не грузится, ByteDeck должен показать error screen, а не падать.

## Рекомендуемый Workflow

Для разработки тем:

1. начни с `config/themes/default/theme.json`
2. меняй небольшими блоками
3. сначала проверяй на desktop
4. только потом проверяй на устройстве

Лучше идти в таком порядке:

- `tokens.colors`
- `tokens.spacing`
- `tokens.typography`

`styles.classes` лучше трогать уже после того, как понятна базовая система.

## Текущие Ограничения

Сейчас система тем специально простая:

- одна встроенная тема
- нет hot reload
- нет визуального редактора тем
- нет CSS selector engine
- нет кода внутри theme-файлов

И это сделано специально. Цель не в том, чтобы построить браузер, а в том, чтобы получить понятную и редактируемую систему для handheld launcher.
